# دليل مهندس النظم الموزعة وتصميم المعماريات (Distributed Systems Architect)

يحدد هذا الدليل العربي إجراءات تصميم النظم الموزعة عالية التوسع، وهندسة قواعد البيانات، وبناء سياسات الصمود، وتحديد عقود واجهات البرمجة (APIs).

## المدخلات ونطاق العمل

متطلبات الأداء والسعة (معدل الطلبات في الثانية RPS للقراءة والكتابة)، وحجم نمو البيانات سنوياً، واتفاقيات مستوى الخدمة (SLAs/SLOs مثل التوافرية 99.99% وزمن الاستجابة)، والحدود الوظيفية للنظام. اقرأ دستور المستودع وملفات البرين الخمسة قبل البدء، واربط مسار المشروع الأساسي.

## خطوات التنفيذ العملية

1. **تحليل السعة ونمط الاستخدام (Capacity & Traffic Analysis)**:
   - تحديد نسبة القراءة إلى الكتابة (Read/Write Ratio).
   - حساب استهلاك الذاكرة وحزم الشبكة عند ذروة الاستخدام.
2. **النمذجة المعمارية وفق نموذج C4 (Architecture Modeling)**:
   - تفكيك النظام إلى سياقات محددة (Bounded Contexts) وخدمات مستقلة.
   - رسم المخططات بصيغة Mermaid المعمارية (سياق النظام، الحاويات البرمجية، المكونات الداخلية).
3. **طبقة البيانات والتخزين المؤقت (Data Layer & Caching)**:
   - اختيار محركات قواعد البيانات الملائمة لكل نمط استعلام (علائقية، مستندات، مفتاح-قيمة، سلاسل زمنية).
   - تحديد استراتيجيات التجزيء (Sharding) والمفاتيح التوزيعية (Partition Keys).
   - تصميم آليات التخزين المؤقت (Cache-Aside, Write-Through) ومعدلات الصلاحية (TTLs).
4. **بروتوكولات الاتصال بين الخدمات (Inter-Service Communication)**:
   - اتصالات متزامنة منخفضة الكمون عبر gRPC أو HTTP/2.
   - اتصالات غير متزامنة عبر نواقل الأحداث (Kafka / RabbitMQ) مع ضمان معالجة الرسائل المتكررة (Idempotent Consumers).
5. **الصمود ومنع نقاط الفشل الفردية (Resilience & SPOF Elimination)**:
   - القضاء على أي نقطة فشل مفردة في كافة الطبقات (موزعات الأحمال، الخوادم التطبيقية، قواعد البيانات).
   - تطبيق قواطع الدوائر (Circuit Breakers) وتحديد معدل الطلبات (Rate Limiting) عبر خوارزميات Token Bucket.
6. **الأمان المعماري (Zero-Trust Security)**:
   - التوثيق المتبادل عبر الشبكة (mTLS) وتفويض الصلاحيات عبر OAuth 2.1 و JWT.
7. **التحقق وتجميع الحزمة**:
   - بناء ملف مواصفات النظام وتمريره عبر أداة الفحص:
     `crewloom run system-design -- --packet system-design.json`.

## المخرجات ومعايير القبول

حزمة مواصفات معمارية متكاملة تجتاز أداة الفحص `system-design`، مرفقة بتقرير معماري مفصل ومخططات تدفق البيانات. يجب أن يثبت التصميم خلوه التام من نقاط الفشل الفردية غير المعالجة، وواقعية حدود التوافرية.

## إدارة الأخطاء والذاكرة

حدّث ملفات البرين في `brain/` بالقرارات المعمارية المنجزة والتحديات والحلول، وتجنب تماماً كتابة أسرار البنية التحتية أو المفاتيح في الذاكرة العامة.
