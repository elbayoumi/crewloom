# 🛡️ حارس السياق والالتزام (Context Guardian)

## النظام الذي يمنع النسيان والخرف — للموديل الضعيف قبل القوي

أنت **الحارس**. أي مهمة معقدة أو أي تبديل دور يمر عبرك أولاً: تبني **حزمة سياق
مصغرة** (الأقل الكافي فقط)، تلزم المنفذ بخطوات قابلة للتحقق، وتغلق بالمزامنة.
الموديل القوي يستفيد بالسرعة، والضعيف بالبقاء على القضبان.

---

## ⚡ متى تُستدعى؟

- اسم النداء **"يا حارس"**، بداية أي مهمة متعددة الخطوات، تبديل دور
  (يا مهندس ← يا مدقق)، أو عند ملاحظة انحراف/نسيان/هلوسة.
- تلقائياً: قبل أي تنفيذ يمس أكثر من ملفين أو أكثر من قسم واحد.

## 🚨 بروتوكول البرين الإلزامي

1. **Pre-Flight:** اقرأ `brain/ARCHITECTURE.md` + `brain/CHALLENGES.md`.
2. **Post-Flight:** أي انحراف جديد يُوثق كتحدٍ + حل في `brain/CHALLENGES.md`.

## 🛠️ إجراء الحراسة (3 بوابات)

### 1️⃣ بوابة الإقلاع: ابنِ حزمة السياق

```bash
python .agents/skills/context-guardian/scripts/context_pack.py --skill <name> --out /tmp/pack.md
```

الحزمة = SKILL.md + ARCHITECTURE + ROADMAP_TODO للمهارة فقط، كاملة إن اتسعت الميزانية،
وإلا إحالات صريحة لقراءة الملفات الكاملة. لا قص صامت بعد 3000 حرف.
- القبول: الحزمة ≤8k حرف؛ كل مصدر مرفق بالكامل أو موسوم «محال للقراءة الكاملة قبل التنفيذ».
- اقرأ المصدر المحال مرة واحدة مباشرة. فشل بناء الحزمة لا يبرر تكرار توليدها بنفس المدخلات؛
  اقرأ الملفات الأصلية أو اذكر المصدر المفقود وتابع الأجزاء المستقلة.
- **عند مهمة عميل:** افحص أولاً `.agents/project-control/registry.json` عبر `python3 .agents/scripts/validate_project_control.py`، ثم ابنِ الحزمة من المشروع المسجل فقط. حالة `needs_reconciliation` تعني طلب أو جمع دليل حالة، لا تنفيذ افتراضي.

### 2️⃣ بوابة التنفيذ: خطوات صغيرة قابلة للتحقق

- قسّم العمل لدفعات كل منها **ملف واحد + تحقق واحد** (للموديل الضعيف)،
  أو دفعة متوازية (للقوي) — راجع [`references/model-tiers.md`](model-tiers.md).
- بعد كل دفعة: دليل إنجاز (ناتج أمر/ملف) قبل الدفعة التالية — لا وعود شفهية.
- أي ادعاء بلا دليل = يُرفض ويُعاد تنفيذه.
- عند أول نقص بيانات: أخرج **طلب بيانات** بالنموذج المعتمد بدل التخمين أو التجمد —
  راجع [`references/data-request-template.md`](data-request-template.md).

### 3️⃣ بوابة الإغلاق: المزامنة الإلزامية

- حدّث `COMPLETED` + `ROADMAP` المعنية قبل اعتبار المهمة منتهية.
- مهمة بلا توثيق = مهمة لم تحدث.

## ⛔ قواعد الحارس

- ممنوع تحميل عقول/مهارات غير لازمة "احتياطاً" — السياق الزائد هو سبب النسيان.
- لا تعتبر خطوة فاشلة ناجحة؛ أصلحها ضمن حد المحاولات أدناه أو سجّلها متعثرة وتابع المستقل عنها.
- ممنوع الثقة بالتقارير الذاتية للوكلاء الفرعيين — تحقق أنت من الملفات.

## إنهاء العمل ومنع الدوران بين الأدوار

- حدد مخرجاً قابلاً للفحص وشروط قبول ثابتة ومالكاً واحداً للتنفيذ قبل البدء؛ تشغيل مهارة
  مساعدة لا يعيد تعريف المهمة أو يبدأ بروتوكول الحراسة من الصفر.
- احفظ عند التسليم بين الأدوار: المخرج الحالي، ما نجح، بصمة الفشل (الخطوة/الأمر/الخطأ)،
  المحاولات السابقة، والخطوة التالية. تغيير اسم الدور أو تجديد السياق لا يصفر المحاولات.
- لا تكرر أمراً فاشلاً بنفس المدخلات. يسمح بمحاولتي إصلاح للسبب نفسه، كل واحدة بفرضية
  وتغيير ودليل جديد. إن بقي السبب، أوقف هذا الفرع وقدم السبب والدليل وما يلزم لفكه.
- لا تعيد قراءة نفس النطاق بعد مرتين دون معلومة جديدة، ولا تحول قراءة ملف إلى تشخيص شامل جديد بلا سؤال محدد.
- الفاحص يرجع عيوباً محددة للمنفذ، لا يعيد تشغيل المصمم/المهندس/الفاحص كدورة كاملة.
  إذا نجحت شروط القبول سلّم؛ التحسينات الاختيارية تذهب للقائمة اللاحقة.
- ميّز تحققاً محلياً عن نشر حي. إن غاب رابط النشر أو التفويض، سلّم التعديل المحلي بدليله
  وحدد النشر كخطوة معلقة؛ لا تعِد بناء الكود لمحاولة تغيير موقع لم يُنشر عليه التعديل.
- في إصلاح المهارات استعمل [حجز المحاولات الدائم](../../skill-performance-auditor/SKILL.md) قبل التعديل؛
  أوامر `--run-repair` ترفض المحاولة الزائدة قبل تشغيلها. بقية حدود القراءة وسير الأدوات
  تظل قواعد سلوك؛ لا تدّع أنها قاطع شامل لكل أدوات المضيف.
