# 🏛️ معمارية تقييم أداء المهارات (Skill Performance Audit Architecture)

```
[استدعاء لمهارة أو كل الأسطول] → [scan_skill_health.py: دليل موضوعي]
  → [قراءة brain/ + استماع لحكم المالك: دليل بشري]
  → [مقارنة triggers مع باقي المهارات لتجنب تداخل]
  → [قرار: KEEP / IMPROVE / RETIRE] → [تسجيل في SKILL_PERFORMANCE_LOG.md]
  → [تسليم: IMPROVE → skill-improvement-engineer | RETIRE → skill-forge-recruiter]
```

## المعيار المزدوج للقرار (إلزامي — لا قرار من طرف واحد)

| المصدر | الوزن | مثال |
|---|---|---|
| بيانات (`scan_skill_health.py`) | يكشف التدهور الصامت غير المُبلَّغ | مهارة بلا إنجاز 60+ يوماً |
| حكم المالك المباشر | يكشف مشاكل الجودة اللي البيانات ما بتلقطهاش | "ردود المهارة دي عامة وملهاش لازمة" |

اعتراض المالك وحده يكفي لبدء تحسين المهارة؛ قرار RETIRE يستلزم مراجعة الدليل الموضوعي وحكم المالك معاً وفق AGENTS.md، ولا يصدر تلقائياً من الفاحص.

## علاقة الأدوار الثلاثة (لا تداخل)

| الدور | المسؤولية | الممنوع عليه |
|---|---|---|
| `skill-performance-auditor` (قيّم) | القرار فقط | التنفيذ |
| `skill-improvement-engineer` (طوّر) | تنفيذ IMPROVE في مكانه | التوظيف الكامل |
| `skill-forge-recruiter` (وظف) | تجنيد بديل RETIRE | إصدار القرار بنفسه |

## عقد القياس الآلي — 2026-09-07

- المدخلات: فاحص البنية `validate_skill.py` الحالي + بيانات التوثيق + سجل
  `.agents/SKILL_INCIDENTS.jsonl` للأخطاء المؤكدة فقط. لا استنتاج لحالة الإصلاح من عناوين Markdown.
- كل حادثة لها skill/id/category/severity/evidence وتاريخ UTC؛ الإغلاق حدث لاحق بدليل تحقق.
  نفس المعرف لا يتكرر؛ عودة العيب في واقعة جديدة تستعمل معرفاً جديداً ونفس category.
- سكور عبء الأخطاء = max(0, 100 − مجموع أوزان الأخطاء المفتوحة). بسيط low=5
  (عيب محدود)، متوسط medium=15 (يحتاج إعادة عمل)، شديد high=30 (يعطل المخرج)،
  حرج critical=50 (فقد بيانات/أثر تشغيلي جسيم). هذه سياسة أولية قابلة للمعايرة وليست نسبة نجاح.
- لا سجل تشغيل = null/«—». نقص وقدم التوثيق لا يخصمان نقاطاً. بنية المهارة تُفحص
  بالفاحص المشترك وتظهر بعدد مستقل، دون مضاعفة عداد حوادث التشغيل.
- التصعيد: 3 أخطاء مفتوحة أو وزن ≥20 أو أي high/critical، أو حادثتان من نفس category
  خلال 30 يوماً مع بقاء إحداهما مفتوحة. العيب القديم المفتوح لا يختفي بمرور الوقت.
  المخالفة البنيوية تصعّد مباشرة؛ تنبيهات التوثيق REVIEW فقط. لا RETIRE آلي بالسكور.
- المخرجات: `.agents/SKILL_HEALTH.md` للعرض البسيط و`.agents/SKILL_HEALTH.json`
  للبيانات/التغير منذ الفحص السابق وقائمة التطوير المسندة إلى skill-improvement-engineer.
  إصلاح كل الحالات المفتوحة يزيل التصعيد، مع حفظ تاريخها في سجل الحوادث.
- السجل مقفول أثناء القراءة/الكتابة؛ الإدخال التالف يفشل صراحة ولا يعطي نتيجة سليمة وهمية.
  نشر التقارير بكتابة ذرية. التشغيل الافتراضي للقراءة فقط، والتحديث بـ --write-report
  أو أوامر تسجيل الحوادث والمحاولات وإغلاقها. لا تعديل تلقائي لكود المهارات من داخل الفاحص.

## التشغيل الدوري والتحقق

- متابعة Codex اليومية مرتبطة بهذه المهمة (id: automation)، الساعة 10 صباحاً بتوقيت القاهرة؛ تراجع الأدلة الجديدة وتنفذ الإصلاحات المحلية الممكنة وتخطر المالك عند تغير مهم فقط. إنشاء الجدولة مؤكد، نجاح التشغيل المجدول يجب التحقق منه عند حصوله.
- تحقق 2026-09-07: validate_skill.py PASS للمهارتين، check_skills_sync.py PASS لـ25 مهارة، 12 اختبار PASS، 17 ملف Markdown بلا روابط مكسورة، anti-slop بلا مخالفات في الملفات الأساسية المعدلة.
- التطبيق الفعلي في Codex تم بقراءة SKILL.md وتشغيل CLI؛ أداة Skill غير متاحة في الجلسة، فلا ادعاء باستدعائها.

## تسلسل تحديث التقرير — مراجعة 2026-09-09
تسجيل الحادثة ثم قراءة الحالة وجمع الفحص ونشر التقرير تتم داخل قفل واحد في .agents/.skill-health.lock. انتظار القفل محدود بعشر ثوان، وكذلك استدعاء git، حتى لا يعلق الفحص. ملفات التقرير تنشر ذرياً كل على حدة؛ زوج Markdown/JSON ليس معاملة ذرية واحدة ويجب مطابقة generated_at عند قراءتهما معاً. جميع ناشري CLI يمرون عبر refresh_report. حجز المحاولة ونتيجتها محفوظان كأحداث attempt_start/attempt_finish في السجل نفسه وتحت القفل نفسه. الحد محاولتان لكل حادثة؛ running يمنع التوازي، وpassed ينتظر إغلاقاً بدليل، وexhausted ينتقل للمراجعة. لا انتهاء تلقائياً للحجز ولا تصفير للميزانية بين الجلسات. --run-repair يحجز قبل إطلاق الأمر ويوقف مجموعة العملية عند المهلة ويسجل النتيجة؛ أدوات الوكيل خارج هذا المسار ليست محكومة به. تفاصيل الاستخدام في SKILL.md.

## تغطية التمارين — 2026-09-13
مصادر JSON مسجلة صراحة في `.agents/SKILL_EVIDENCE_SOURCES.json`؛ كل مصدر قائمة غير فارغة بها skill/task/status/scope/evidence. المسارات نسبة لجذر المستودع، وملفات خارج الجذر أو الوصف النصي للسجل تظهر كدليل غير متاح. المصدر المفقود أو التالف أو اسم مهارة مجهول يوقف النشر بدلاً من إسقاط الصف.
أولوية العرض: عائق/فشل مسجل، ثم دليل ناقص، ثم تمارين جزئية؛ غياب التمارين غير مقاس. لا حالة «كامل» مشتقة من ملفات قديمة أو عدد تمارين. لا علاقة حسابية بين هذه الحالات وسكور الحوادث. وقت توليد التقرير ليس وقت التشغيل، ولا ينفذ الفاحص أوامر من مصادر الأدلة.
## حدود الملخص الآلي — 2026-09-14
NO_OPEN_INCIDENTS يصف سجل الحوادث فقط. operational_readiness يظل unverified، والتغطية الجزئية لا تتحول إلى اعتماد تشغيل أو قرار KEEP آلي. السكور يقيس عبء الحوادث ولا يقيس جودة الموظف.
