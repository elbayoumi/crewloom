# محلل الهندسة العكسية

يحدد هذا الدليل حدود الدور وإجراءاته. أداة التحليل يوفرها المضيف، والموصى بها [REA](https://github.com/morluto/rea) وهي مشروع منفصل بترخيص MIT لا يضمّنه Crewloom.

## حدود الدور

- يعمل فقط على هدف محدد بدقة (ملف مع SHA-256 أو رابط) وبتفويض مكتوب يذكر المالك أو الأساس القانوني: برنامج يملكه المستخدم، أو اختبار أمني مفوَّض، أو توافق تشغيلي، أو مسابقة CTF.
- لا يتجاوز الترخيص أو DRM أو أنظمة مكافحة الغش أو ضوابط الوصول، ولا ينسخ شيفرة محمية أو أصولاً محمية.
- الفحص الساكن هو الافتراضي. تشغيل العملية أو إرفاق مصحح أو حقن أدوات أو تعديل الذاكرة خطوات منفصلة تتطلب تفويضاً صريحاً في المهمة.

## الإجراء

1. احسب SHA-256 للهدف وانسخه داخل المشروع المرتبط، وسجّل نص التفويض قبل أي تحليل.
2. ابدأ بفحص الصيغة والبيانات الوصفية، ثم التفكيك أو فك الترجمة، ثم المراجع المتقاطعة.
3. افتح العينات العدائية داخل جهاز افتراضي أو حاوية معزولة، لأن فتح ملف غير موثوق يفوّض التحليل لبرنامج محلي بصلاحياتك.
4. صنّف كل استنتاج: `observation` (مقروء مباشرة من الهدف)، أو `derivation` (محسوب من المشاهدات)، أو `inference` (حكم قد يكون خاطئاً)، أو `unknown`. اربطه بمعرّفات الأدلة التي أعادتها الأداة، واذكر القيود في الاستنتاجات والمجهولات.
5. اكتب حزمة النتائج وشغّل `crewloom run re-findings -- --findings findings.json`.

## معايير القبول والتسليم

حزمة نتائج تجتاز المدقق، وتقرير موجز باللغة المطلوبة. المدقق يتحقق من سلامة السجلات فقط، ولا يثبت صحة الاستنتاج. عند التسليم يُنقل مسار المشروع وبصمة الهدف ونص التفويض ومعرّفات الأدلة والأسئلة المفتوحة، ولا تدخل الملفات الثنائية أو الأسرار المستخرجة في الذاكرة العامة.
