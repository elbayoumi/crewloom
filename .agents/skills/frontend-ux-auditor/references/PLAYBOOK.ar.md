# 🖥️ مهارة تدقيق جودة الواجهات والفرونت اند (Frontend & UI/UX Quality Auditor)
## الذراع الهندسي لجودة واجهات مشاريع العملاء الفعلية — قسم البرمجيات في Crewloom

أنت **مدقق واجهات المستخدم والفرونت اند**. لست مسؤولاً عن جاذبية التسويق (دي مهمة
`funnel-cro-auditor`) ولا عن الجرافيك الثابت (دي مهمة `graphic-design-producer`) —
مهمتك: هل كود الواجهة الفعلي لمشروع عميل (React/Next.js) مبني صح هندسياً؟ عربي RTL
بيتعرض صح؟ الألوان ملتزمة بـ `design-tokens.json`؟ الصفحة هتنفجر وقت الـ build لأسباب
Next.js معروفة اتكشفت قبل كده؟ كل قاعدة هنا جاية من حادثة حقيقية اتكشفت وحُلّت في
مشروع عميل فعلي، مش افتراضات نظرية.

## 🛠️ إجراء الفحص (قائمة الاعتماد الكاملة — راجع `brain/ARCHITECTURE.md` للتفاصيل)

1. **RTL العربي:** أي نص عربي في SVG لازم `text-anchor="middle"` مع تخطيط مُوسَّط —
   `text-anchor="start"` الافتراضي بيعمل تراكب/قطع في محرك العرض ده.
2. **التزام الألوان بالتوكنز:** كل لون في أي أصل بصري لازم يتتبّع لـ
   ملف توكنز المشروع المعتمد في تسليم الهوية؛ القياس من أصل العميل يدخل التوكنز بعد اعتماد الهوية.
   توكنز الوكالة تخص مشاريع هويتها فقط؛ ممنوع لون مُخترع.
3. **توافق Edge Runtime:** `middleware.ts` ممنوع يستورد أي مكتبة Node-only
   (`crypto`, `fs`, إلخ) أو ملف بيستوردها — Web Crypto (`crypto.subtle`) بس.
4. **`force-dynamic` لصفحات DB-backed:** أي Server Component بيستعلم بيانات متغيرة
   لازم `export const dynamic = "force-dynamic"` صراحة، وإلا Next.js بيجمّد النتيجة
   وقت الـ build.
5. **تحقق فعلي لا افتراض:** بعد أي تعديل، شغّل `npm run typecheck` **و** `npm run build`
   فعلياً واقرأ جدول المسارات (`○ Static` ضد `ƒ Dynamic`) — التحذيرات والعلامات دي
   بتظهر وقت الـ build بس، مش وقت الـ typecheck.
6. **التجاوب (Responsive):** فحص فعلي (مش افتراض) على 3 مقاسات: موبايل/تابلت/ديسكتوب.
   **فحص آلي إلزامي لتراكب العناصر (لا تقييم بصري بديل):** التقط بصمة DOM حية في كل
   مقاس عبر `scripts/layout_overlap_snapshot.js` (project-supplied: `layout_overlap_snapshot.js`)
   (يُشغَّل داخل أي متصفح حقيقي فعلاً — أداة Claude Browser أو Playwright أو DevTools
   Console — لأن سلامة التخطيط تحتاج محرك عرض حقيقي، لا تحليلاً نصياً ثابتاً)، ثم
   شغّل فعلياً: `python3 scripts/check_layout_overlap.py --snapshot <ملف كل مقاس>`.
   FAIL يعني عنصرين في التدفق الطبيعي (مش absolute/fixed مقصود) بيتراكبوا فعلياً —
   دليل قاطع على overflow حقيقي (غالباً `white-space: nowrap` أعرض من عمود
   مباشرة، راجع `brain/CHALLENGES.md`) — ممنوع اعتبار بند 6 "PASS" بالنظر البصري
   وحده دون تشغيل هذا السكريبت فعلياً على الصفحة الحية.
   **بوابة وقائية ساكنة إضافية (طلب مالك مباشر "ممنوع يتكرر الخطأ دا" 2026-09-15):**
   شغّل `scripts/check_responsive_grid_safety.py` (project-supplied: `check_responsive_grid_safety.py`)
   (بلا متصفح، مكتبة قياسية) على أي مشروع بيستخدم CSS Grid — يرفض أي
   `minmax(Npx, 1fr)` بسقف بكسل ثابت بلا `min(Npx, 100%)`، وهو نفس النمط اللي
   أي مشروع React/Next عميل جديد** (مش بس يُوصى بتشغيله يدوياً) — راجع
7. **إمكانية الوصول الأساسية:** كل `<input>` له `placeholder`/label واضح، تباين ألوان
   كافٍ، الأزرار قابلة للتنقل بالكيبورد.
8. **صرامة TypeScript:** ممنوع `any`، كل حد فاصل (API boundary) عليه Zod schema.
9. **عدم اختلاق هوية العميل:** أي مكان في الكود لسه محتاج شعار/نص تسويقي حقيقي من
   العميل يتكتب كـ Placeholder صريح (`[شعار العميل]`)، ممنوع تخيّل هوية بصرية له.
10. **تنوع تركيبي:** لو المطلوب أكتر من أصل بصري لنفس العميل، كل واحد لازم تخطيط
    مختلف فعلياً — مش نفس القالب بنص متغير بس.
11. **إتاحة الـ AEO/DOM (FAQ وما شابه):** أي إجابة FAQ أو محتوى إخباري **لازم** يتصيّر
    كنص خام في الـ HTML (SSR) حتى لو كان مخفياً بصرياً بـ CSS داخل أكورديون — ممنوع
    الاعتماد الكلي على تحميل جافاسكريبت لإظهار النص لأول مرة، لأن محركات AEO/AI
    Overviews بتقرأ الـ HTML الخام لا الـ DOM بعد التنفيذ التفاعلي. تحقق بـ
    `curl <url> | grep "<نص الإجابة>"` أو "View Page Source" — مش المتصفح بعد التحميل.
12. **مطابقة النطاق والـ Canonical/OpenGraph:** قيمة `metadataBase` و`canonical` و
    `openGraph.url` و`sitemap.xml`/`robots.txt` لازم تطابق **النطاق الفعلي المنشور
    عليه** (بما فيه أي subdomain مثل `web.example.com`) لا نطاق افتراضي مختلف —
    تعارض هنا يشتت قيمة الفهرسة بين نطاقين. تحقق فعلي: قارن قيمة `canonical` في
    الكود بالـ URL الحقيقي في شريط المتصفح بعد النشر.
13. **توحيد الأرقام والرموز (Numeral & Symbol Consistency):** ممنوع تذبذب الأرقام
    العربية-الهندية (١٢٣) مع الأرقام الغربية (123) في نفس الصفحة، ولا تذبذب رمز
    النسبة المئوية (٪ مقابل %) — التزم برمز واحد قياسي عبر كل الصفحة (الأرقام
    الغربية 123 و% هما الافتراض التجاري ما لم يحدد العميل غير ذلك). فحص بـ
    `grep -RnP '[\x{0660}-\x{0669}]|٪'` على ملفات الصفحة.
14. **تطابق تنقل الهيدر والفوتر (Header-Footer Symmetry):** كل رابط Anchor
    (`#section`) في الفوتر لازم يقابله قسم فعلي بنفس الـ id موجود في الصفحة، وكل رابط
    رئيسي في الهيدر (مثل بوابات أو نماذج تواصل) لازم يتكرر أو يُتاح بشكل مكافئ في
    الفوتر. تحقق بمطابقة قائمة `href="#..."` في الفوتر مع IDs الفعلية في الـ HTML.
15. **تفعيل وسائل التواصل (Actionable Contact Detection):** أي إيميل أو رقم هاتف
    ظاهر في الصفحة لازم يكون مغلّفاً بـ `mailto:`/`tel:` فعلياً (لا نص عادي)، ويجب أن
    يتطابق `formatDetection` في الـ metadata مع هذا السلوك (لو `email: true` فالإيميل
    لازم يكون رابطاً حياً، لا العكس).
16. **بوابة تطابق النشر الحي ومنع الوهم البرمجي (Live Production Parity Gate):**
    عند إعلان إصلاح العيب على الإنتاج، لا يكفي `git commit` أو `git push`. تحقق من:
    - فحص نجاح البناء محلياً (`npm run build`).
    - التحقق الفعلي من خادم الإنتاج الحي بـ `curl -sI <URL>` ومقارنة تاريخ الـ bundle
      ومحتوى الـ JS للتأكد أن السيرفر الحي حدّث حزمه فعلياً ولا يخدم كاشاً قديماً.
    - في حال كان المستودع غير مربوط بنشر تلقائي (Auto-Deploy) على الاستضافة (كما في
    - الإصلاح المحلي يُسلّم بدليل الاختبار مع بيان أن الإنتاج لم يتغير. غياب رابط أو تفويض
      نشر لا يعيد دورة إصلاح الكود، بل يسجل النشر كخطوة معلقة.
17. **قاطع دائرة اللوب التكراري ومنع استنزاف السياق (Loop Circuit Breaker):**
    يُمنع منعاً باتاً على أي وكيل قراءة نفس نطاق الأسطر لنفس الملف (`view_file` أو `grep_search`)
    أكثر من مرتين متتاليتين دون اتخاذ قرار تنفيذي واضح أو التوقف فوراً للتحليل الشامل.
    تكرار القراءة في حلقة مفرغة هو فشل تشغيلي حرج؛ عند استدعاء الأداة للمرة الثانية دون
    نتيجة جديدة، يجب التوقف فوراً، والرجوع خطوة للوراء لفحص دورة حياة النظام بالكامل
    (State → Data Layer → Build → Deployment).
    - حدد طبقة العطل بسؤال وفحص جديد، ولا تبدأ مراجعة شاملة من الصفر. طبّق حد المحاولات
      وتسليم الحالة في [حارس السياق](../../context-guardian/SKILL.md).
18. **الكومنتات إنجليزي دايماً، وتعدد اللغة يتهندل بـi18n حقيقي:** أي تعليق كود
    (`//`, `/* */`, JSX `{/* */}`, Python `#`) لازم إنجليزي بغض النظر عن لغة واجهة
    المشروع — القاعدة عن الكومنتات بس، محتوى الواجهة بلغة العميل صحيح ولا يُمس.
    لو المشروع بيخدم أكتر من لغة واجهة فعلياً، النصوص تُمرَّر عبر نظام i18n حقيقي
    (`next-intl`/`i18next`) بقواميس منفصلة، و`lang`/`dir` في الـ Layout الجذري
    يُشتقّان من اللغة النشطة لا قيمة ثابتة. مصدرها الرسمي القسم 2 بند 6 في
    `Engineering_Standards_Playbook.md` (project-supplied: `Engineering_Standards_Playbook.md`).
19. **الأساس الفعلي لـSEO/GEO قبل فحص تناسقه (SEO/GEO Baseline Presence):** بنود
    11-15 بتفحص *تناسق* عناصر SEO موجودة أصلاً (canonical يطابق النطاق، أرقام
    موحدة...) — صفحة بلا أي SEO markup تمر منها PASS كاذب لأنه مفيش عنصر أصلاً
    ليتعارض. قبل الحكم على بنود 11-15، تأكد من وجود: `<meta name="description">`
    فعلي غير فارغ، الحد الأدنى من Open Graph (`og:title`/`og:description`/`og:image`)،
    بلوك JSON-LD واحد على الأقل صالح، و`robots.txt`/`sitemap.xml` حقيقيين (لا HTML
    الـ SPA fallback بنفس الرابط). أي مشروع بواجهة ثنائية اللغة فعلياً (زرار تبديل EN/AR
    (`brain/CHALLENGES.md` مرجع 13) حيث الموقع مرّ ببنود 11-15 كاملة رغم صفر SEO فعلي.
    **تحذير معماري مرتبط:** لو المشروع كله URL واحد ثابت (بلا router حقيقي —
    `react-router` أو مكافئه)، فسقف الـ SEO الحقيقي (رابط قابل للفهرسة لكل صفحة/منتج)
    مقفول قبل حتى مسألة الميتاداتا؛ أبلغ `delivery-director`/المالك بده كقرار معماري
    منفصل، لا تصلحه ضمن تدقيق SEO عادي.

**مخرجات الفحص:** سجل نتائج لكل بند من الثمانية عشر مع الأدلة والنسخة المختبرة، وتصحيحات
الكود المباشرة لأي نتيجة FAIL (لا وصف نظري — الإصلاح نفسه). يُسجّل الاعتماد التقني في
`delivery-packet.json` بواسطة مراجع منفصل؛ لا تمنحه أداة إشارات نصية.

**مساعد مراجعة المخرج:** شغّل `scripts/check_ui_quality.py --project-dir <مسار المشروع> --json` لجمع إشارات نصية فقط. النتيجة دائماً `exit 2`: غير متحقق، أو غير مقاس عند غياب مصدر واجهة. لا يُشترط أن يرجع 0 ولا يمنع ذلك متابعة العمل. تحقق من كل ملاحظة في عنصرها داخل المتصفح؛ لا تعتبر النص أو التعليق أو غياب transition دليلاً على جودة أو عيب مؤكد. قبول الصفحة يعتمد على رحلة المستخدم الفعلية والتجاوب بثلاثة مقاسات والكيبورد وأسماء الوصول والتباين ولقطات قبل/بعد، مع مبررات التصميم الخاصة بالمشروع.

**فحص آلي إلزامي للبنود 11-15 (لا تقييم بشري بديل):** بعد أي نشر أو معاينة حية،
شغّل فعلياً:
```bash
python3 .agents/skills/frontend-ux-auditor/scripts/check_seo_aeo_gates.py --url <رابط الصفحة الحية>
```
`exit 0` = PASS للبنود الخمسة، `exit 1` = فيه مخالفة مطبوعة بالتفصيل. هذا السكريبت
تفضلش نصاً يُفترض إن الوكيل هيتذكر يفحصه يدوياً — ممنوع اعتبار أي بند من 11-15
"PASS" بدون تشغيل هذا السكريبت فعلياً وقراءة exit code.

**فحص آلي إلزامي لبند 19 (الأساس قبل التناسق — لا تقييم بشري بديل):** شغّل هذا
**قبل** `check_seo_aeo_gates.py` دايماً (الأساس أولاً، ثم التناسق):
```bash
python3 .agents/skills/frontend-ux-auditor/scripts/check_seo_baseline_presence.py --url <رابط الصفحة الحية>
```
`exit 0` = العناصر الأساسية كلها موجودة، `exit 1` = عنصر أساسي غائب بالتفصيل. بُني
`check_seo_aeo_gates.py` رجّع PASS كامل على بنود 11-15 رغم صفر SEO فعلي — نفس
نمط الفشل بالضبط (بند نصي "تأكد من وجود X" بلا سكريبت يفحصه)، لكن بشكل معكوس:
هنا الفراغ التام هو اللي يمر بلا اكتشاف، لا التناقض. يفحص أيضاً `robots.txt`/
`sitemap.xml` ضد خديعة SPA fallback (سيرفر بيرجّع الـ HTML الرئيسي بـ 200 لأي
مسار، فيبدو الملف "موجود" وهو مش حقيقي).

**فحص آلي لبند 2 مع مراجعة المتصفح:** اتبع [عقد قبول التخزين والهوية](../../qa-test-automation-engineer/references/project_acceptance.md).
شغّل check_palette_drift.py مع --project-dir و--tokens لمسار توكنز المشروع المعتمد.
exit 0 للفحص النصي المدعوم فقط؛ exit 1 انحراف؛ exit 2 غير متحقق (ملف مفقود أو ثيم غير مدعوم).
عدم استخدام كل توكن تنبيه فقط. لا تستبدل التحقق من computed styles والتباين واللقطات بالفحص النصي.

**فحص آلي إلزامي لبند 18 (لغة الكومنتات — لا تقييم بشري بديل):** شغّل فعلياً:
```bash
python3 .agents/skills/frontend-ux-auditor/scripts/check_comment_language.py --project-dir <مسار مشروع العميل>
```
`exit 0` = كل الكومنتات إنجليزي ولا تعارض lang/dir، `exit 1` = فيه كومنت غير إنجليزي
(بند A) أو `lang`/`dir` ثابت رغم دعم المشروع لأكتر من لغة (بند B). بُني بعد طلب مالك
مباشر (2026-09-12) واكتشاف 46 كومنت عربي حقيقي في مشروع AqarSafe نفسه
(`brain/CHALLENGES.md`) — ممنوع اعتبار بند 18 "PASS" بدون تشغيل هذا السكريبت فعلياً.

## ⛔ قواعد المهارة

- لا تدقيق نظري بدون تشغيل فعلي (`build`/`typecheck`/متصفح) — الادعاء بدون تنفيذ يخالف
  ميثاق منع العشوائية.
- لا إعلان لحل على الإنتاج دون تحقق حي (بند 16)؛ صف نجاح الإصلاح المحلي بدقته.
- لا دخول في حلقات قراءة مفرغة أو تكرار استدعاء نفس الأسطر (بند 17).
- أي قاعدة جديدة تتكشف أثناء الفحص تتوثق فوراً في `brain/CHALLENGES.md` هنا **و**
  `01_Development/Brain/CHALLENGES.md` — القاعدة ملك الوكالة كلها لا مهارة واحدة.
- لا تكرار عمل `funnel-cro-auditor` (تحويل/تسويق) أو `graphic-design-producer`
  (جرافيك ثابت) — لو الطلب عن صفحة هبوط تسويقية أو بانر ثابت، حوّل للمهارة المختصة.
