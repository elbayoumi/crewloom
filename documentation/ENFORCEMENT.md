# Managed execution enforcement

Managed command steps execute against a temporary snapshot containing only declared inputs. The project directory is never mounted. The snapshot is read-only except for individual declared output files. The trusted broker validates nonempty output bytes, input fingerprints and destination paths before publishing artifacts. Failed commands publish nothing.

## Grouped artifact publication

Every declared output group is published as one recoverable transaction, not as independent file writes. Before the first destination is touched the broker checks the whole group and every input fingerprint, refuses links, hardlinks, duplicate canonical destinations, project control paths and trusted runtime paths, and caps outputs, staged payloads, backups, journals and receipts. It then stages the group and a backup of every destination it will replace under protected `.crewloom`, records the journal, and applies the group under the project lock with the project lock held for the whole publication and its recovery.

A failure part-way through is rolled back to the recorded original content and mode, or removes only the files that attempt itself created. The whole journal is validated before any rollback byte is written, so either every destination is restorable or none is touched. A writer killed part-way through leaves its journal, and the next managed publication, project entry or workflow run reconciles it before it reads workflow state, freezes context, evaluates a publish gate or records acceptance. A destination that no longer matches its journal blocks reconciliation, is left untouched, and keeps its journal for manual review.

Releasing a finished or reverted transaction removes only what this protocol staged in it: the journal and the per-index `backup/<index>.bin` and `payload/<index>.bin` copies its own record names. Every entry inside a stage is checked before the first is removed, so an unknown nested file — an operator's own notes, or a copy named for an index no record claims — is never deleted, and it is reported with its journal, staged bytes and transaction kept for manual reconciliation. Nothing is deleted recursively and no folder is cleaned around it. A rollback that was proved before it was written stays complete in that case; only the residue needs an operator.

Before any rollback byte is written the broker re-runs its own destination check on every recorded path instead of trusting a digest alone. A matching digest says the bytes are the ones this attempt wrote; it says nothing about what the name is now. A destination that became a hardlink, a directory, a symlinked path, or a control or trusted location after the crash is therefore refused with every staged original and the journal left in place. Journals are inspected and bounded before they are read and before they are parsed: a journal must be a private regular file with one link within 1 MiB, far above the size of the widest group the broker can publish, so a corrupt or oversized one is refused rather than loaded into the recovery path.

This is deliberately **not** claimed to be an instant multi-file atomic filesystem change: a reader that ignores the project lock can observe a group half applied. What is guaranteed is narrower and real. Managed writers serialise on the same lock, each group is recoverable, and an interrupted group converges instead of accumulating. Containers have no network, Docker socket or forwarded host environment. Their root filesystem is read-only; capabilities are dropped, privilege escalation disabled, and runtime metadata hidden. Limits are 1 GiB memory, two CPUs, 128 processes, 128 MiB temporary storage, and 4 MiB per writable file. Plans set a wall timeout of 1–3600 seconds. Declared inputs total at most 16 MiB; outputs total at most 4 MiB; each set contains at most 128 files. Backups a group may roll back into total at most 16 MiB, and one publication journal is at most 1 MiB. Inputs and existing destinations cannot be hardlinks; redirected output paths are rejected. Outputs cannot modify the trusted Crewloom checkout.

Commands must write declared files in place. Atomic rename over bind-mounted output files and undeclared build artifacts are unsupported. Use `/tmp` for intermediate work, then copy results into the declared files. Include imported modules and configuration in inputs.

## Path comparison across filesystems

A name is compared as a filesystem can resolve it, not as it was spelled. Case and Unicode normalization are folded before every reserved-name, collision and containment check, and existing paths are compared by device and inode as well, so `Result.txt` and `result.txt` are one destination even where no rule explains it and even where the host resolves both spellings identically. This is deliberately conservative and portable: two names that fold together are refused as one destination on a case-sensitive filesystem too, where they would really have been two files. Nothing is probed and no host setting is read, so the same input is refused on a developer Mac, in CI and in a container. The trade is real and accepted: a submission that differs only in case is rejected on every platform instead of being accepted on some.

## Model generation

Managed `model` steps default to tool-free provider RPC. Set `host` to `openai` or `anthropic`, specify an explicit supported `model` identifier, and configure `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` locally. Do not put credentials in plans. The provider receives the selected prompt and declared textual inputs; it receives no filesystem, shell, browser or delegated-agent tools. Returned artifacts must match the declared output schema and pass the same publication broker.

Requests use fixed HTTPS endpoints without redirects or ambient proxies. Responses are capped at 2 MiB, prompts at 256 KiB and generated output at 4096 tokens. A killable worker enforces the wall timeout. The project ledger permits at most 32 model attempts across workflow IDs; two failures with unchanged evidence block retries. These limits are not a dollar spending cap: configure account spending controls with the provider.

Prompt size is bounded by the transport the selected host actually uses, in UTF-8 bytes, and an oversized prompt is refused at capability preflight before any attempt, batch reservation, probe or launch. `codex` and `claude` read the prompt from stdin and `openai`/`anthropic` send it in the request body (262,144 bytes); `opencode` receives it as one argv element (131,072 bytes). The recorded limit is the adapter's documented bound, not the model's context window, which is never guessed.

Native `codex` and `claude` CLI steps are rejected by default. The operator can explicitly pass `--allow-host-cli` for compatibility with existing plans. This runs an external host outside the enforced model boundary. A plan cannot enable that exception itself. Historical CLI evaluations establish their recorded results, not enforcement by this provider gateway.

## Trust boundary

Docker, the operating system, the trusted broker and the person operating the host remain trusted. Manual task steps and agents with arbitrary host access are outside this boundary. Repository instructions cannot force such agents to obey. Project locks coordinate this runner; they do not protect against another host process modifying files. A recorded digest and mode prove which bytes were staged and replaced, not ownership of a path against a privileged process that can change a destination between validation and write; the deterministic shapes the broker refuses — links, directories, symlinked and control paths, unrecognised staged content — are refused, and unprivileged concurrent mutation by an unrelated process remains outside what any check here can prove. A lock whose owning process is provably gone is reclaimed under an exclusive reclamation claim, verified against the exact inode it read, so a competing live owner is never deleted with a stale record. Reclamation never follows a symlinked lock, claim or owner path and never deletes unrecognised claim contents; an unrecognised claim blocks the root for manual reconciliation instead. Reclaiming a lock does **not** stop a command or container that outlived the process that recorded it: inspect surviving containers yourself. Review declared inputs before sending them to an external provider. Provider authentication and live model success require local credentials; mock transport tests alone do not establish either.

Self-Editing Mode should produce changes in a separate project or Git worktree. Review and test the resulting changes before updating the trusted runtime. Running a model with write access to its own active enforcement code would invalidate this boundary.

## Concurrent coordination

The [task coordinator](COORDINATOR.md) inherits this boundary rather than extending it. Each task runs the enforced command executor inside its own Git worktree, so a task cannot reach the root project, another worktree, the Docker socket or the host network. Only the verified declared outputs of a task are committed, so generated instruction context, `.gitignore` edits, role memory, user files and `.crewloom` never leave a worktree as task output, and a Git hook that refuses the commit leaves the worktree and its artifact for inspection.

Taking a batch reserves the root with the same record a managed workflow writes, so this is coordination between managed writers and not a weaker second path into the project. A declared-label review names a reviewer and carries no signature; a credential-verified review is signed by the project's reviewer registry with its issuance epoch, and both revocation and a replayed consumed decision stop a publication. Reclaiming batch ownership proves the previous controller released its kernel lock; it does not stop a container that outlived that controller, and the coordinator terminates nothing it does not own. Publication is one recorded `--ff-only` fast-forward of a reviewed candidate, not a reset, an arbitrary checkout, a history rewrite, a push or a GitHub merge, and Git's own atomicity limits still apply to that single operation.
