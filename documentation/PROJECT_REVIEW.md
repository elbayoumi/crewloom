### Counterexamples and required corrections

1. **W04 — concurrent receivers can both accept.** `continuation.accept` validates then writes owner.json without an encompassing lock or compare-and-swap. 2. **W04 — mandatory checkpoints are fail-open.** With `write_checkpoint` raising a synthetic OSError, both command steps produced outputs and no latest checkpoint existed. The existing continuation suite deliberately accepts that behavior. Separate required durable pre-dispatch state from optional telemetry: refuse effects when the required checkpoint cannot persist. Acceptance: no command/provider call or output after a pre-dispatch write failure; after-effect failures retain uncertain evidence for reconciliation.
3. **W09 — the documented batch output ceiling is per request.** With `max_output_tokens=100`, two requests of100 each were admitted and finished with reported output200; a third request with unknown output bound was also admitted. COORDINATOR.md says these limits apply to the whole batch. Reserve aggregate output bounds or rename/document a per-request limit and add a distinct aggregate contract. Unknown bounds must not silently satisfy a guaranteed ceiling. `LIMIT_KEYS` has no cost cap: reported `cost_usd` is accounting, contradicting the report's statement that token/cost caps work from reported usage. Acceptance must distinguish byte bounds, requested ceilings, actual usage and unenforceable native-host limits.
4. **W09 — cancellation can leave descendants running.** A tracked parent spawned a sleeping child. Cancellation terminated the parent, deleted its tracking entry and returned success while the child remained alive. The review explicitly cleaned up its own disposable child. Track and stop a managed process group/descendants with identity checks; prove unrelated processes survive. Existing single-child cancellation tests remain useful but miss this topology.

A reused name is therefore not protected by the PID-start check. This is source/stub evidence, not a reproduced real-container incident. Retain immutable ID and owner identity, verify before deleting and run real disposable-container acceptance plus a reused-name negative control.
6. **W01/W02 — source identity fixtures depend on the host environment.** Locally the checkout test fails `dirty_paths:1 !=0`: importing the copied module creates an unignored __pycache__. Disabling fixture bytecode writing makes that assertion pass. CI additionally sees installed Crewloom0.6.0.dev0 where another fixture expects no distribution metadata; CI installs the package before testing. Do not weaken assertions or hide failures with a global test skip.
