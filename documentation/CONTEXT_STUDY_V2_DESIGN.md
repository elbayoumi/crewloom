# Context study v2: dependency-closure map (design)

Status: design only. No runtime change, no provider call and no result is claimed here. It
follows the first frozen run recorded in [CONTEXT_STUDY.md](CONTEXT_STUDY.md).

## 1. What the first run actually showed

The selected-map arm scored 0/11 on all eight scored Codex trials, while full-source scored
11/11 on all nine. The stored artifacts give a precise cause:

| Arm | Import form in the generated module | Held-out outcome |
|---|---|---|
| full-source | `from src.money import ...` | all cases ran |
| selected-map | `from .money import ...` | `ImportError` on 11/11 cases |

Required helper bodies were present in both arms. The full-source prompt contains other
modules that import each other as `src.<name>`; the selected-map prompt held the helper body
and a names-only symbol map, so nothing showed the package import form. The arm therefore
measured a missing convention, not missing logic. The old map listed only
`kind name:line-range`, which carries no parameters and no import form.

## 2. Goal and non-goals

Goal: a bounded context that keeps the facts a tool-free model needs to write a correct,
importable module, at far fewer bytes than the full source.

Non-goals: no claim of general quality or speed, no change to the frozen v1 arms, prompts or
results, no retry of v1 failures, no real-client data.

## 3. The map

A deterministic, byte-bounded context built from the repository index, in this order:

1. **Package import contract.** One line stating how modules import each other, derived from
   the repository's own statements (for the fixture: modules are imported as `src.<module>`),
   followed by every intra-package import statement verbatim, with the file it appears in.
2. **Required bodies.** Unchanged: the full text of every module the task contract names.
3. **Dependency closure.** The full text of any in-package module imported by a required body,
   transitively, while the budget allows; otherwise its signature lines.
4. **Signature lines.** For every other module, each `def` and `class` line as written in the
   source (name, parameters, defaults) plus the first docstring line, instead of the current
   name and line range.

Measured on the fixture, without any provider call. The raw definition lines of the whole
package are 1,082 bytes and the raw import lines 353 bytes; with the first docstring lines the
signatures total about 3,330 bytes, and the structured JSON entries add more. The exact rendering
produced by the implementation gives prompts of 11,192 to 11,524 bytes against 20,781 to 20,913
for full source and 8,150 to 8,597 for the v1 selected map. So the closure arm adds roughly 3 KB
to the v1 prompt and is about 54% of full source. The frozen test bounds it below 60% of full
source and within 4,096 bytes of the v1 prompt. These are sizes of context, not savings in
tokens or cost; the study must measure those.

Everything is derived from the index and the files; nothing is generated by a model, and a
file the budget cannot represent is named as omitted rather than silently dropped.

## 4. Offline information-sufficiency gate

The v1 failure cost 36 provider calls to discover something a static check finds in
milliseconds. v2 adds a gate that runs before any call:

- For each task, take the frozen reference solution.
- Extract its import statements and every helper symbol it calls.
- Require each one to be derivable from the arm's prompt: the import form appears as a verbatim
  statement or in the contract line, and each called helper has its body or signature present.
- A task or arm that fails the gate blocks the study. Prompts are never reworded after seeing grades.

Acceptance of the gate itself, as for every new gate in this repository: the v1 selected-map
prompts must be rejected (they carry no `src.` import form) and the full-source and v2
prompts must be accepted. The gate is a necessary condition for a fair arm, not proof that a model succeeds.

## 5. Study v2 preregistration (outline)

| Item | Choice |
|---|---|
| Arms | `full-source` and `closure-map`; v1 `selected-map` is not rerun |
| Tasks | the same three frozen tasks and held-out cases; grader and fixtures unchanged |
| Hosts | Codex first. OpenCode joins only after its 14 malformed structured responses and 4 timeouts are diagnosed |
| Repeats | 3 per task, arm and host; fixed new seed; balanced order; no early stopping |
| Calls | 18 for Codex alone |
| Failures | retained and counted in denominators; no replacement or rewording |
| Reported | held-out pass rate, prompt bytes, input, cached and output tokens, cost only if supplied, duration, paired differences with sample counts |
| Allowed claims | only what the paired scored rows show for these three synthetic tasks |
| Not claimed | general quality, universal speed, billing savings |

Freeze before the first call: tasks, contracts, grader, fixtures, prompts, models, order, seed
and the closure-map generator digest. Verify them again afterwards.

## 6. Pinned interfaces

The frozen acceptance file `scripts/test_study_closure_map_boundaries.py` fixes these entry
points, so implementation cannot drift from the design:

| Interface | Contract |
|---|---|
| `repo_map.build` symbols | each symbol gains `signature` (its source line, stripped) and `doc` (first docstring line or empty); the parser version rises to 3 |
| `repo_map.closure_context(project, value, required, budget)` | returns `import_contract`, `imports` (path and verbatim statement for every intra-package import, including function-local ones), `closure` (path and full text, transitive, in deterministic order), `signatures` (path, signature, doc) and `omitted`; the package name is derived from the repository; mandatory content that cannot fit raises `ValueError` |
| `evaluate_hosts.study_prompt(task, 'closure-map', ...)` | mandatory content byte-identical to full-source; `treatment.mode` is `closure-map` |
| `evaluate_hosts.study_sufficiency(task, condition, reference_text, project)` | returns `sufficient` and a `missing` list; relative imports and undefined imported names are never sufficient |
| `evaluate_hosts.study_plan_v2(hosts, repeats, seed, contracts)` | arms `full-source` and `closure-map`, seed `20261006`, 18 trials for one host |

v1 stays byte-identical: its prompts, navigation text (apart from the parser version token),
plan and mandatory digests are pinned by the same file.

## 7. Implementation plan

1. **Independent frozen tests first** (written by the parent, never edited by the implementer):
   the sufficiency gate cases above, map determinism, byte bounds, budget omission reporting,
   and a clean accepted case.
2. **Index**: capture each definition's source line and first docstring line in
   `scripts/repo_map.py` `structure`; bump the parser version so stale caches are refused.
3. **Render**: a closure mode in `render` implementing sections 1 to 4.
4. **Study runner**: a `closure-map` condition and a v2 protocol identifier in
   `scripts/evaluate_hosts.py`, leaving v1 behaviour untouched.
5. **Gate**: the offline sufficiency check wired into study preparation.
6. Runtime changes are made through OpenCode `opencode/space-bunny-free`, then verified
   independently, as for earlier work.

## 8. Prior art

Repository maps that show definition lines are an established idea; Aider's repo map is the
best-known open implementation (Apache-2.0, about 49,000 stars, last pushed 2026-05-22 when
checked on 2026-10-05). It is a reference for the shape of the output only. This design is
deterministic, byte-bounded and gated by a preregistered study, and no code is copied from it.

## 9. Risks

- The import contract may help in this fixture and not generalize; three synthetic tasks cannot show otherwise.
- A closure that grows past the budget degrades to signatures; the study reports how often.
- The fixture's package-relative imports may not exist in other languages; JavaScript and
  TypeScript need their own import-form rules before any claim there.
